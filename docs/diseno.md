## Sistema visual

- Tema claro, minimalista y espacioso.
- Colores: negro `#000000` para texto, iconos y bordes; blanco `#ffffff` como lienzo; gris claro `#f3f3f3` para superficies secundarias; gris `#e2e2e2` para bordes; gris medio `#757575` para metadatos; lima `#b8ff65` como acento ambiental.
- El lima va en fondos de bloques o secciones, nunca como relleno de botones, color de icono, enlace o texto pequeño.
- DM Sans, pesos 400, 500 y 700. Alternativa: Inter o sans serif equivalente.
- Tipografía orientativa: cuerpo 14–16 px; subtítulos 24 px; títulos 38–48 px; display hasta 58 px. Titulares grandes en negrita, compactos y con interletraje negativo. Mantener buena lectura en móvil.
- Tarjetas y bloques con radio aproximado de 30 px; navegación tipo píldora hasta 40 px.
- Diseño plano, sin sombras ni degradados. Usar bordes finos, fondos y espacio en blanco para jerarquía.
- Contenido centrado con ancho máximo cercano a 1200 px y separación generosa.
- Ilustración lineal negra, sin relleno, en fondos lima solo cuando aporte personalidad y no compita con el contenido.
- No incorporar otros colores saturados salvo necesidad funcional de accesibilidad/estado; primero proponer una solución compatible con la paleta.

## Login cinematográfico

El acceso es la pantalla expresiva: composición tipo póster, gran bloque lima, titular de gran escala e ilustración lineal futbolística en negro (balón, portería o campo). El formulario de usuario y contraseña debe ser evidente y fácil de usar, con acceso al registro y aviso de aprobación pendiente. Adaptar a móvil priorizando el formulario. Sin vídeo de fondo, fotografías pesadas, degradados ni animación llamativa; cualquier movimiento debe ser sutil, opcional y respetar reducción de movimiento.

## Aplicación diaria

El resto es más estático, ligera y funcional: fondo blanco/gris, tarjetas claras con bordes discretos, controles legibles y poca animación. Reservar el lima para bloques destacados, no salpicarlo por todos los controles. Priorizar asistencia, votaciones, equipos, pagos, resultados y administración. La inspiración visual nunca debe reducir contraste, accesibilidad o claridad.

## CSS

El usuario prefiere que la interfaz no tenga una apariencia genérica de Tailwind. Cuando se elija la tecnología, proponer CSS tradicional, CSS Modules o el sistema propio del framework/plantilla. No añadir Tailwind automáticamente; si una plantilla elegida depende de él, explicarlo y acordar si se mantiene o se adapta.
